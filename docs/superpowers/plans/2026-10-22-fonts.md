# Fonts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fonts as a second Library kind: the owner uploads TTF/OTF faces, the server checks them, draws a preview, keeps every version, and the app lists the Trending fonts in the owner's order and downloads them by id or by legacy family name.

**Architecture:** Server: a `FontAsset` detail table (additive migration), a `font` kind descriptor, a `probeFont` inspector and a `renderFontPreview` renderer (fontkit + resvg-js), a `FontsService` that ingest delegates to for font uploads and new versions, font lifecycle rules in `AssetService`, and font endpoints in the public catalogue. Dashboard: Library › Fonts (list with previews and the legacy checklist, Trending order, Categories, font page with new version).

**Tech Stack:** NestJS 11, Prisma 7, Jest 30, fontkit 2, @resvg/resvg-js 2 (server); Next.js 16, TanStack Query 5, shadcn/Radix, Vitest 5 (dashboard).

**Spec:** `slimshot_server/docs/superpowers/specs/2026-10-22-fonts-design.md`

Repos: server tasks S1–S10 in `slimshot_server`, dashboard tasks D1–D3 in `slimshot-admin`, both on a new branch `feat/fonts` from `main`.

## Global Constraints

- Sounds do not change in behaviour: every existing sound test passes unchanged except where a task says so.
- Migration is additive only, written by hand; never run `migrate`, `db push` or `seed` against Neon.
- TTF (`00 01 00 00` or `true`) and OTF (`OTTO`) only; refuse WOFF (`wOFF`), WOFF2 (`wOF2`), collections (`ttcf`), variable fonts (`fvar`), colour/emoji fonts (`COLR`, `CBDT`, `sbix`, `SVG `), fonts lacking any of A–Z, a–z.
- Declared types `font/ttf` (`.ttf`), `font/otf` (`.otf`); cap `UPLOAD_FONT_MAX_BYTES` default `10_485_760`.
- Family = name ID 16 else 1; style = name ID 17 else 2; full = name ID 4; PostScript = name ID 6.
- Unique per face: (family, style) compared case-insensitively, among fonts that still have a `FontAsset` row.
- Preview: PNG 480 × 160, transparent, white text, scaled to fit the width, vertically centred; text = display name (`Asset.title`). Key prefix `slimshot/fonts/previews/`; file role `specimen`.
- Font files key prefix `slimshot/fonts/`; every version kept; current = `isPrimary`; `variant: { version: n }`.
- Published once → never unpublished or deleted. Never published → deletable, which frees its (family, style).
- App: `GET /catalog/fonts?category=trending`, `GET /catalog/fonts/:id`, `GET /catalog/fonts/by-family/:familyName` (exact, style `Regular`), download via existing `POST /catalog/assets/:id/download`.
- The 19 legacy families, exact spelling: Montserrat, Lato, Oswald, Bebas Neue, Playfair Display, Pacifico, Dancing Script, Poppins, Raleway, Inter, Nunito, Lobster, Caveat, Abril Fatface, Righteous, Permanent Marker, Press Start 2P, Cinzel, Sacramento.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. No push, no deploy.

## Review Focus

1. Two uploads of the same family + style racing past the service check: the database's unique key must turn the second into a clear refusal, and its object must be deleted → test in S7 ("a duplicate caught by the database is refused like any other").
2. A download after a new version must hand out the **new** file, never an older one → test in S9 ("downloads the current version, never an older file").
3. A new version whose preview fails to draw must keep the old preview and stay published → test in S7 ("a failed redraw keeps the previous preview").
4. The Trending category hidden or not yet created: the list 404s, but a font by id and by family still works → test in S9.
5. Reorder with an id that isn't a font in Trending (or a duplicate id) must be refused, not half-applied → test in S8.

### S7: FontsService — upload, new version, preview

**Files:** `src/modules/fonts/fonts.service.ts` (+ spec), `fonts.module.ts`; modify `ingest.service.ts` (delegate), `create-upload-ticket.dto.ts` (`assetId` also allowed with `role: original`), `ingest.service.spec.ts`

- [ ] **Step 1: Tests** (`fonts.service.spec.ts`, prisma/storage stubs, real fixture bytes through a stub adapter):
  - new font: FontAsset row with Lato names, `version 1`, `sortOrder` = (max sortOrder of fonts in the same category) + 1, title set to `fullName`, original file `isPrimary` with `variant { version: 1 }`, specimen file under `slimshot/fonts/previews/`, asset `ready`, cache bumped `catalog:font`.
  - refuses a duplicate face (service check) with "Lato Regular is already in the library" and deletes the object.
  - **a duplicate caught by the database is refused like any other** (stub create throws P2002 → same refusal, object deleted).
  - refuses each `probeFont` refusal with its message, object deleted, asset `failed` (as audio).
